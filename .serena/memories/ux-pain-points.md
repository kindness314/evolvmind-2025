## 二、一条核心结论

> 系统已能：存内容、结构化、画图谱、做搜索。
> 还缺的：让用户**感受到**系统理解了他的内容、发现了有价值的关系、能主动总结提醒，且 AI 结果可信、可解释、可回溯。
>
> 下一阶段不只是补功能，而是要补**用户感知价值**。

## 三、十二大体验痛点 → 技术方案映射

### P1. 输入后即时反馈不够强 ⭐ 第一优先

| 维度 | 内容 |
|------|------|
| **用户感知** | 保存内容后看不到系统做了什么，只看到节点和线。用户不知道"它真的理解了吗？" |
| **期望体验** | 保存后立刻展示：本次摘要、新增节点、新增关系、与历史关联、可点击进图谱 |
| **技术方案** | **O1 捕获处理状态** — 为 `captured_info` 增加 `processing_status/embedding_status/graph_status/processing_error/processed_at` |
| **核心不变量** | 原始内容先保存；AI 失败不能删原文；状态持久化；失败可见；只重试失败步骤 |
| **涉及文件** | `CapturePage.tsx`, `HomePage.tsx`, `ItemDetailPage.tsx`, `api/embed.ts`, `api/graph/embed.ts`, 新 migration |

### P2. 冷启动价值不明显

| 维度 | 内容 |
|------|------|
| **用户感知** | 数据少（3-10条）时图谱稀疏，搜索/推荐几乎无产出。"我是不是要先导入很多才有用？" |
| **期望体验** | 即使只有 3 条也给出即时洞察：已识别主题、内容关联、建议补充方向 |
| **技术方案** | (1) Demo 样例空间让新用户直接感受最终效果 (2) 批量导入 Markdown/PDF/浏览器收藏 (3) 少量内容即时洞察 |

### P3. 多模态内容未真正解析

| 维度 | 内容 |
|------|------|
| **用户感知** | 图片/音频/PDF/Word 入口存在，但仅保存元数据。"我上传了 PDF，为什么系统没读懂？" |
| **期望体验** | OCR、ASR、文档正文提取。未实现时明确告知用户"暂未解析原文" |
| **技术方案** | 当前非文本文件保留元数据 + 明确提示解析能力待实现；不伪造解析结果 |

### P4. 知识图谱好看但不好用

| 维度 | 内容 |
|------|------|
| **用户感知** | 节点多→一团乱麻；关系缺解释；不知道重点在哪；不知道点哪个 |
| **期望体验** | 分类清晰、节点详情含解释、关系可追溯原文、可编辑/合并/删除 |
| **技术方案** | **O6 图谱聚焦缩放** + 四个 PENDING 缺陷修复 |
| **具体缺陷** | (1) 线性 fitScale 不感知邻域大小 (2) 详情面板打开后节点被裁切 (3) 分类视图长标签溢出 (4) 移动端缩放感不一致 |
| **性能优化** | force-graph 动态 import（`React.lazy`），降低 ~840KB chunk 首屏影响 |
| **涉及文件** | `KnowledgePage.tsx`, `App.tsx` |

### P5. 搜索结果缺解释和上下文

| 维度 | 内容 |
|------|------|
| **用户感知** | 搜到了但不知道为什么相关，"下一步应该看什么？" |
| **期望体验** | 匹配原因、高亮相关片段、关联节点、可跳转图谱/原文 |
| **技术方案** | **O2 搜索结果补查** — 恢复 `sourcePreviews`，统一 Bearer token/REST 查询，禁止 fallback service role |
| **涉及文件** | `api/search.ts`, `api/graph/search.ts` |

### P6. AI 结果不可追溯、不可修改

| 维度 | 内容 |
|------|------|
| **用户感知** | 摘要/节点/关系/推荐都是 AI 产出，"准不准？AI 是不是瞎猜的？" |
| **期望体验** | (1) 可追溯——每个节点/关系指向原始内容 (2) 可编辑——合并节点、改名、删关系、改分类、标记推荐不相关 (3) 置信度或来源说明 |
| **技术方案** | 跨 O1-O6 的基础能力：节点→原文回溯、关系→来源展示、节点编辑/合并 API |

### P7. 近期总结未形成产品习惯

| 维度 | 内容 |
|------|------|
| **用户感知** | 用户不只要"你记录了 A/B/C"，要的是主题分布、新增节点、与历史的新连接、建议下一步 |
| **期望体验** | 过去 7 天关注主题、新出现的重要节点、与历史的新连接、建议下一步方向 |
| **技术方案** | **O5 ProcessPage**（删除或改为真实处理中心） + **O1 状态追踪** |
| **涉及文件** | `ProcessPage.tsx` → 删除或改为读取当前 scope 真实记录的 pending/processing/failed |

### P8. 主动推送未落地

| 维度 | 内容 |
|------|------|
| **用户感知** | 推送必须相关+节制+可解释，否则变成打扰。"系统像广告一样烦" |
| **期望体验** | 首页"智能建议卡片"——推荐理由清晰、不推送通知 |
| **技术方案** | 第一版：首页推荐卡片（"你可能想回顾" + 推荐理由），不做系统通知 |

### P9. 时间演化缺实用视角

| 维度 | 内容 |
|------|------|
| **用户感知** | 用户不需要炫酷动画，要的是：最近新增了什么、哪些主题变强了、关注点如何变化 |
| **期望体验** | 时间筛选 + 新增节点/边列表 + 主题增长趋势 + 最近变化高亮 |
| **技术方案** | 第一版：时间筛选 + 变化高亮；动画回放后置 |

### P10. 长期留存缺"回来的理由"

| 维度 | 内容 |
|------|------|
| **用户感知** | 有"记录"和"搜索"，缺每天回来的钩子 |
| **期望体验** | 每日/周总结、最近变化、相关推荐、未整理提醒、主题形成提示 |
| **技术方案** | 依赖 P7+P8+P9 落地后形成留存闭环 |

### P11. 隐私安全未向用户说明

| 维度 | 内容 |
|------|------|
| **用户感知** | 数据安全？AI 是否外传？删除是否真删？Demo 是否共享？敏感资料是否用于训练？ |
| **期望体验** | 数据作用域说明、Demo/真实数据隔离说明、AI 调用说明 |
| **技术方案** | Settings 页面增加隐私说明 + Demo 模式明确标注；**关联 O4 Settings 真实化** |

### P12. 输入入口不够快/移动端体验不够轻

| 维度 | 内容 |
|------|------|
| **用户感知** | 用户很忙，希望随手丢进去系统自己处理 |
| **期望体验** | 快速记录入口、移动端优化、减少手动补充字段 |
| **技术方案** | 移动端适配增强（Web Share API、原生文件选择）；PWA 化（`vite-plugin-pwa`） |
